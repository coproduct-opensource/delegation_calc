## 1. The reframe

`#[dlc_d::service(budget, cap, flow)]` becomes `#[dlc_d::agent_service(...)]`, its axes
agent-governance-meaningful, with a fourth (delegation) axis:

```rust
#[dlc_d::agent_service(
    cap      = Invoke<Tool> @ issuer,     // admission control: only an `issuer says Invoke<Tool>` may act
    flow     = chi <= l_low,              // cross-agent isolation (ASCII canonical; `χ ⊑ ℓ_low` is sugar)
    budget   = Faults<1> & FairDelivery,  // failure envelope: tolerate exactly 1 fault
    delegate = attenuate_only,            // multi-hop delegation may only narrow authority
)]
struct Ledger {
    #[replicated] balance: Labeled<u64, chi>,
}
```

`cargo build` green ⟹ the deployed binary's admission control is machine-checked
(`capability_safety`), honest governance nodes agree even under a Byzantine minority
(`rust_byz_agreement`), and the enforcement is provably exercised (§4 of the positioning memo).
This is the formal-proof analogue of ACP's admission control — where ACP model-checks 3 TLA+
invariants, this compiles a certificate the verified checker validates and carries to deployed
Rust.

## 2. Surface syntax (Q2/Q3 resolved)

- **ASCII canonical, Unicode sugar.** `flow = chi <= l_low` is the canonical form (keyboard- and
  `syn`-tokenizer-friendly); `flow = χ ⊑ ℓ_low` is accepted and lowered to the same AST. No
  behaviour depends on the surface form.
- **Labels as phantom const-generics + a `FlowsInto` trait.** A store field is
  `Labeled<T, L>` where `L` is a zero-size label marker; `flow = a <= b` requires
  `L_a: FlowsInto<L_b>`. Tier-1 (rustc) rejects an ill-flowed assignment as an ordinary trait
  bound error — a genuine `rustc` diagnostic, not a Lean goal.
- **`cap = Invoke<Tool> @ issuer`.** Each `#[write]`/`#[invoke]` method demands a
  `Cap<Invoke<Tool>, Issuer>` value in scope; Tier-1 makes its *absence* a type error.
- **`delegate = attenuate_only`.** A delegation combinator (`Cap::attenuate`) that can only
  narrow the carried `Prop` (backed by `Term::Attenuate`); the type signature forbids widening.

### 2.3 The capability token (Q4)

The `Cap<Invoke<Tool>, Issuer>` value is not a bare phantom — it carries the runtime
`says`-credential (a `Sign`-term + Ed25519 signature) that `dlc-crypto::signed_term::verify_in_keyring`
already checks, and that Phase 2 encodes to/from a Biscuit block. So the compile-time gate (the
token must be present and well-typed) and the runtime credential (the signed token on the wire) are
the *same object* viewed at two times — resolving the R6.0 Q4 tension (phantom vs signed term).

## 3. The spine: a verified certificate checker (Q5 + Q8)

The macro is a proc-macro (untrusted token-manipulation). Rather than trust it, we make the build
gate on a **verified checker** that validates the obligation the macro emits. A wrong certificate is
*rejected*, so a green build is sound **regardless of macro correctness** — which is precisely what
"verify the macro" needs to mean for soundness (Q8): the macro is out of the TCB, the checker is in
it, and the checker is proved.

### 3.1 What already exists (the checker is substantially built)

- **`crates/dlc-core/src/decide.rs :: decide_pure / infer`** — a Rust decision procedure for the
  proof-checking problem, already in the Aeneas-translated `dlc-core` tree
  (`lean/DLC/Aeneas/DlcCore/Funs.lean :: decide.infer`). This *is* the Rust-side certificate
  checker Q5 asks for.
- **`lean/DLC/Decidability.lean :: decideLean`** — the hand Lean mirror of `infer`, with
  **soundness** (`decideLean Γ M = some φ → Nonempty (Deriv Γ M φ)`,
  `t1_propositional_soundness_prop`) and **completeness** (`t1_propositional_completeness`), combined
  into `PropDeriv.decidable_nonempty` (T1, proven).

So "accept ⟹ a real derivation exists" is already a theorem — for the hand mirror.

### 3.2 The missing link (the increment): `infer_square`

What is *not* yet proved is that the **Aeneas image of the Rust checker** agrees with the hand
mirror: an `infer_square` correspondence

```
decide.infer ctx term  =  ok (decideLean ctx term)      (under the honest U32/closedness fences)
```

exactly analogous to the `decided_square` / `byz_decided_square` transports already landed
(`lean/DLCD/CorrespondenceConsensus.lean`). Composing it with T1 soundness gives the headline:

```
rust_decide_sound :  decide_pure problem = ok true  →  Nonempty (Deriv problem.ctx problem.term problem.prop)
```

— **the deployed Rust checker's acceptance implies a real typing derivation.** This is the verified
certificate checker. It is a bounded, well-understood transport (the same shape as the consensus
squares), not new metatheory.

### 3.3 Extending the checker to the commit-I obligation

The macro's admission obligation is *commit-I typeability*: `command(M, c, ℓ) : Replicated(φ⊃φ) ℓ`,
which requires `c : issuer says capProp` and `M : φ⊃φ`. `infer` already handles `Sign` (says-I) and
`⊃`; the increment is to (a) extend `infer`/`decide_pure` to the `command`/`commit-I` arm (or a
DLCD-level `decide_command`), and (b) prove its soundness reduces to `capability_safety` via
`command_typing_inversion` (already proved, `lean/DLCD/CapSafety.lean`). Staged after §3.2.

### 3.4 Why this verifies the macro (Q8)

Soundness of "green build ⟹ admission-safe" depends only on `rust_decide_sound` (checker soundness),
**not** on the macro emitting the right thing. A buggy or adversarial macro that emits an invalid
certificate is rejected by the verified checker → compile error. The macro therefore need not be
verified for *soundness*; it must be good for *ergonomics* (§4) and *completeness* (it should accept
valid programs), which the golden-obligation test suite pins. This is the honest, achievable reading
of "verify the macro now": soundness is machine-checked and macro-independent.

## 4. Error ergonomics (the "easy" requirement)

Tier-1 obligations are ordinary `rustc` errors already (missing `Cap`, failed `FlowsInto` bound).
Tier-2 (a rejected certificate) must render as a source-located `rustc`-quality diagnostic — the
build script maps a checker rejection back to the offending method span and prints "this write is
not authorized by any `Invoke<Tool> @ issuer` capability in scope", not a Lean goal. This is the
single place verified systems lose "easy," so it is a first-class requirement, tested by
`trybuild` compile-fail fixtures.

---

## 5. Two-tier discharge, summarized

| Obligation | Tier | Discharged by |
|---|---|---|
| a `Cap<Invoke<Tool>, Issuer>` is in scope for each write | 1 | rustc (type error on absence) |
| flow respects labels (`FlowsInto`) | 1 | rustc (trait-bound error) |
| the write is commit-I typeable (real `says`-credential) | 2 | the **verified checker** (`decide_pure` → `rust_decide_sound` → `capability_safety`) |
| budget/fault envelope | 1+2 | const-generic `Faults<f>` (Tier-1) + `budgeted_guarantee_voids_over_budget` (the type empties over budget) |

## 6. Staging (green-to-green increments)

1. **`infer_square` + `rust_infer_sound`** — verify the existing Rust checker (§3.2). ✅ **DONE**
   (2026-07-24): `rust_infer_sound` proven axiom-clean + CI-gated — the deployed `decide.infer`
   inferring a type ⟹ a real `Deriv` on the agreeing fragment. The checker is *sound-by-theorem*.
   (`rust_decide_sound` for the user-CLAIMED prop, via the `prop_eq_sound` eq-soundness web, is a
   deferred strengthening — see `spec/r6.2-inc1 §6.2`.) The load-bearing "compilation is the proof"
   piece is banked.
2. **commit-I certificate extension** (§3.3) — checker covers the admission obligation; soundness to
   `capability_safety` via `command_typing_inversion`. (Deferred: `command`/`runCmd` are outside the
   currently-verified fragment; the propositional says-credential + store-transformer are IN it.)
3. **`dlc-d-macro` proc-macro** — parses the envelope, emits Tier-1 types + a Tier-2 certificate
   (a `TypingProblem`); golden-obligation test suite pins its output. 🔨 **IN PROGRESS**:
   - ✅ crate scaffolded (`crates/dlc-d-macro`, proc-macro; syn/quote).
   - ✅ envelope-axis parser (hand `syn::Parse` over the `@`/`<=` grammar; source-located errors).
   - ✅ `dlc-d` facade crate + Tier-1 vocabulary (`Cap`/`Invoke`, `FlowsInto` + `assert_flows_into`,
     `Faults<const F>`, `labels{Public⊑Secret}`).
   - ✅ **Tier-1 lowering**: `agent_service` lowers each present axis onto the governed `fn` as a
     sibling anonymous `const _`: `cap` → a `PhantomData<Cap<Invoke<Tool>, Issuer>>` type anchor
     (undefined cap type = compile error); `flow` → `const _: () = assert_flows_into::<Src, Sink>()`
     (illegal flow = source-located `E0277` trait-bound error); `budget` → `const _: Faults<f> =
     Faults`. Verified by `trybuild`: `tests/ui/good.rs` compiles, `tests/ui/illegal_flow.rs`
     (`Secret <= Public`) fails with the pinned diagnostic pointing at the offending `Secret` span.
   - ✅ **Tier-2 pipeline proven** (`crates/dlc-d/tests/certificate.rs`): the admission obligation
     is discharged by a *certificate* — a `dlc_core::TypingProblem` (the commit-I store-transformer
     `λx:atom_cap. x : atom_cap ⊃ atom_cap`, in the verified fragment F) — validated by the real
     `dlc_core::decide::decide_pure`. Acceptance ⟹ (by `rust_infer_sound`) a real `Deriv` exists, so
     the macro is **out of the TCB**: a bogus/mistyped certificate is *rejected* (tested), meaning a
     green run is sound regardless of macro correctness. Hand-written here to prove the pipeline
     against the real checker; the macro *emits* an equivalent generated check next. Fence: proves
     *typeability* (crypto realization of the `says`-credential is Phase 2); validated at `cargo test`
     time (a build.rs build-time gate is the §4 follow-up).
   - ✅ **Macro emits the certificate**: from the `cap` axis, `agent_service` emits a hidden
     `#[test] fn __dlc_d_cert_<fn>()` that builds the store-transformer `TypingProblem` (cap atom =
     FNV-1a of the tool name) and asserts `decide_pure`. `dlc-d` exposes the `dlc_core` runtime it
     references via `#[doc(hidden)] pub mod __rt`, so a user crate depends only on `dlc-d`. Verified:
     `cargo test -p dlc-d` runs `__dlc_d_cert_governed_write ... ok`. Green run ⟹ verified checker
     accepted ⟹ real `Deriv` — fully automated, macro out of the TCB. (Fence: the emitted certificate
     is the always-typeable identity store-transformer — it wires the pipeline; obligations that
     *fail* on misconfiguration are a follow-up.)
   - ✅ **Tier-1 cap-presence enforcement**: when a `cap` axis is present, `agent_service` appends a
     `_dlc_d_cap: Cap<Invoke<Tool>, Issuer>` parameter to the governed `fn`, so every CALLER must
     present the capability witness of the exact tool/issuer. Verified by `trybuild`
     (`tests/ui/missing_cap.rs`): an unauthorized call fails with `E0061` ("argument #1 of type
     `Cap<Invoke<FileWrite>, Admin>` is missing"). Both core violation classes are now compile
     errors: **illegal flow** (`E0277` trait-bound) and **unauthorized invocation** (`E0061`).
     (Fence: `Cap::new()` is freely mintable — the witness's *validity* is backed by the Tier-2
     certificate; a gated mint tying minting to a verified credential is a follow-up.)
   - Next: budget-breach as a compile error (over-`Faults<f>`); a certificate that can *fail* on
     misconfiguration; a build.rs build-time gate (§4); the Phase 3 runnable governed-agent demo.
4. **build integration + diagnostics** (§4) — the checker runs in a build step; rejection → a
   source-located compile error; `trybuild` good/bad fixtures. (Diagnostics ✅ via trybuild; a
   build.rs build-time gate is the remaining piece.)
5. **Phase 3 demo** consumes it. 🔨 **STARTED**: `crates/dlc-d/examples/governed_agent.rs` — a
   runnable `cargo run --example governed_agent -p dlc-d` governed tool (`SendEmail@Ops`, flow
   `UserData ⊑ AuditLog`, `Faults<1>`). It runs (prints the governed invocation), its certificate
   is validated by the verified checker at `cargo test`, and its banner contrasts the compile-time
   proof with the runtime-governance state of the art (IBCT/Governed MCP/PAuth). The emitted cert
   is now `#[cfg(test)]`-gated so it validates at test time and is excluded from example/release
   builds (no dead code, not shipped).

Increment 1 is the highest-leverage first step: it turns the already-shipped Rust checker into a
verified one, which is the load-bearing piece for the whole "compilation is the proof" claim.

## 7. Honest fences

- **Propositional fragment first.** `decide_pure` covers the propositional fragment (`⊃`, `says`,
  `∧`, `∨`); the commit-I extension (§3.3) is staged. Full-calculus decidability (temporal / IFC /
  linear) stays out of the checker, as it does in T1.
- **Partial-correctness rides along** (`decide.infer`'s Aeneas image, like all `rust_*`, under the
  `ok`/no-overflow fences).
- **Runtime IFC stays type-level** (positioning memo §5); the `flow` axis is a build-time claim.
- **Ergonomics is real work** (§4) — the one place "easy" can still break.
- **Interop credential** (the Biscuit/RFC-8693 realization of the cap token) is Phase 2.
