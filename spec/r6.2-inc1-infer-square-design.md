# R6.2 increment 1 — `infer_square` + `rust_decide_sound` (design)

*Design memo. 2026-07-24. Branch `dlc-d/phase0-carve`. Phase 1 build increment 1 of the
agent-governance program (`spec/r6.2-agent-service-envelope.md` §3, §6). Design-first because
this is the largest single transport in the program; the proof is staged below.*

---

## 0. Goal

Turn the already-shipped Rust proof-checker (`crates/dlc-core/src/decide.rs :: decide_pure` /
`infer`) into a **verified** one, so a green `cargo build` of an `#[dlc_d::agent_service]` implies a
real typing derivation (hence `capability_safety`), *independent of the macro*. The headline:

```
rust_decide_sound :
  decide.infer ctx term = ok (some prop)  →  Nonempty (Deriv (DecCtx ctx) (DecTm term) (DecPr prop))
```

obtained by composing two pieces:

1. **`infer_square`** (the new transport): the Aeneas image of the Rust checker agrees with the
   hand mirror `decideLean` under decode —
   `decide.infer ctx term = ok ((decideLean (DecCtx ctx) (DecTm term)).map DecPr)` (fences below).
2. **T1 soundness** (already proved, `lean/DLC/Decidability.lean`):
   `decideLean Γ M = some φ → Nonempty (Deriv Γ M φ)`
   (`t1_propositional_soundness_prop`), for the propositional fragment.

So `infer_square` is the whole of the new work; `rust_decide_sound` is a two-line composition.

## 0a. CORRECTION after reverse-engineering (2026-07-24): the decode is CONCRETE work, not "a small missing piece"

`DecTm`/`DecPr` in `Correspondence.lean` are **only type abbreviations** (`syntax.Term → DLC.Term`)
and the decode *functions* are **abstract/deferred** ("Abstract in R2.2b") — the consensus squares
take them as parameters with hypotheses. `infer_square` cannot: `decideLean`'s soundness is about a
*concrete* hand `Deriv`, so stage 1a must **define a concrete decode** over the whole grammar. This
is the bulk of increment 1. It is mechanical (a 1:1 structural map, no mutual recursion — `decProp`
never calls `decTerm`), and every mapping is now fixed (§1a). Reusable idiom (`Correspondence.lean`):
`.val` for `UScalar → Nat` and `Vec/Array → List`; decode structures field-by-field.

### 1a. The concrete decode, fully specified (write this first, green, then the lemmas)

Leaf decodes (hand types: `DLC.{Principal,PrincipalId,Signature,Obligation,ActionId,TimeBound}`,
`DpBudget` in `Graded.lean`, `Label := nucleus_ifc_kernel.CapabilityLattice`):

- `decLabel : ifc.Label → DLC.Label := fun _ => DLC.Label.bottom` — a **total default**. A faithful
  `Vec U32 → CapabilityLattice` decode is *impossible* (established at `lean/DLCD/Transport.lean:85`),
  and it is **sound here** because every label-carrying constructor (`at`, `liftLabel`, `declassify`,
  `command`, `replicated`) is **fail-closed in `decideLean`** — the checker never inspects a label, so
  the decode need only be total, not faithful.
- `decTimeBound t := ⟨t.epoch_ms.val⟩`;  `decSignature s := ⟨UInt8.ofNat s.alg.val, s.bytes.val.map (fun b => UInt8.ofNat b.val)⟩`.
- `decPrincipalId a := ⟨a.val.map (fun b => UInt8.ofNat b.val)⟩` (Aeneas `Array U8 32`);  `decActionId` identical (Aeneas `Vec U8`).
- `decDpBudget d := ⟨d.epsilon_micros.val, d.delta_micros.val⟩` (confirm `Graded.DpBudget` field names).
- `decPrincipal` / `decObligation` — structural 1:1 (`Atom→atom` via `decPrincipalId`; `ActOf→actOf`,
  `Within→within` via `decTimeBound`, `DpBudget→dpBudget`, `Tensor/Lolli/Top/Bot` 1:1).

`decProp : syntax.Prop → DLC.Prop'` — 13-ctor 1:1: `Top→top, Bot→bot, Atom i→atom i.val,
Imp→imp, And→and, Or→or, Says p→says (decPrincipal p), SpeaksFor p q→speaksFor …, At φ ℓ→at (decProp φ) (decLabel ℓ),
Boxed o φ→boxed (decObligation o) …, Within τ φ→within (decTimeBound τ) …, Tensor→tensor, Lolli→lolli,
Replicated φ ℓ→replicated (decProp φ) (decLabel ℓ)`.

`decTerm : syntax.Term → DLC.Term` — 1:1 to the hand ctors `var/lam/app/sign/verify/delegate/attenuate/
boxed/discharge/liftLabel/declassify/now/withinIntro/pair/fst/snd/inl/inr/case/tensorIntro/letTensor/
saysBind/letSays/sfExtract/command/runCmd` (`Var i→var i.val`; sub-decodes via the leaves + `decProp`).
**One read remaining next turn:** dump the *complete* Aeneas `syntax.Term` ctor list
(`lean/DLC/Aeneas/DlcCore/Types.lean`, esp. whether it carries `RunCmd`) to confirm the arm set aligns
exactly with the hand `Term`.

`decCtx c := ⟨c.additive.val.map decProp, c.linear.val.map decProp⟩`.

New file `lean/DLC/DecideDecode.lean` (or a `DecideSquare.lean`), wired into `lean.yml` LIBS; the
decode is a pure-definition, no-`sorry`, immediately-green artifact — the foundation the correspondence
lemmas (§2) build on.

## 1. Why this is tractable (the infrastructure exists for the LEMMAS)

Once the decode (§1a) is defined, the correspondence is the same shape as the landed `decided_square`
/ `byz_decided_square` / reduce-squares, reusing `lean/DLCD/Correspondence.lean`:

- **Decode abbreviations** `DecTm`/`DecPr` (types only, §0a) — the concrete functions are §1a; a
  `DecCtx` is defined there
  (additive/linear are `Vec syntax.Prop`; decode is `List.map DecPr` on each).
- **Clone-is-identity** lemmas `propClone_id`, `termClone_id` (`Correspondence.lean` L200–210) —
  `decide.infer` clones `phi`/`ctx` on every arm; these discharge the clones to `ok`.
- **The reduce-square pattern** (`apply_command`/`reduce_with_fuel` squares) — the established recipe
  for peeling the `Result` monad + `ControlFlow` (`?`-operator via `Try_trait.branch`) that
  `decide.infer` threads on every recursive call.
- **The var-arm Lean correspondence** `ctxLookup_eq_checker_additive` (`lean/DLC/CtxWellFormed.lean`)
  — `ctxLookup Γ i = decideLean Γ (var i)`; the analogue on the Aeneas side (Slice.get ↔ `[i]?`) is
  the var-arm's hard content.

## 2. The proof, staged (each stage a green-to-green increment)

**1a — `DecCtx` + helper lemmas.** Define `DecCtx : judgment.Ctx → DLC.Ctx` and prove:
- `uscalar_cast_index`: the `UScalar.cast .Usize i` on the var index equals `i.val` (no overflow,
  the honest `< 2^32` fence).
- `slice_get_decode`: `core.slice.Slice.get (deref additive) idx` decodes to
  `(DecCtx ctx).additive[idx]?` — the var-arm lookup correspondence (reuse the Vec/Slice lemmas the
  reduce-squares already use).
- reuse `propClone_id` / `termClone_id`; add `ctxClone_id` if needed.

**1b — the var arm.** Compose 1a: `decide.infer ctx (Var i)` decodes to `decideLean (DecCtx ctx)
(var i)`, matching both the additive-hit and the linear-singleton (`len = 1`, `idx = 0`) branches.
This is the hard arm (U32/Slice/index + the linear fallback); everything else is structural.

**1c — the structural arms.** For `Lam`/`App`/`Sign`/`Verify`/`Pair`/`Fst`/`Snd`/`WithinIntro`/
`Inl`/`Inr`/`TensorIntro`/`Case`: each `decide.infer` arm is `branch`-on-recursive-call then rebuild;
each `decideLean` arm is `match`-on-recursive-call then rebuild. With the IH + `propClone_id` +
`Try_trait.branch` unfolding, each is a mechanical `simp`/`split`; the `beq` guards
(`App`, `Case`, `Verify`) reuse `Prop.beq`↔`Prop'.beq` decode-agreement.

**1d — fail-closed arms.** `SaysBind`/`Boxed`/`Declassify`/`LiftLabel`/`Now`/`Delegate`/`Attenuate`
return `none` in *both* `decide.infer` and `decideLean` (both fail-closed outside the fragment) — a
one-line `rfl`/`ok none` each. (This is why the fragment restriction is free: the checker rejects
these, so soundness never needs them.)

**1e — capstone `infer_square`** by structural induction over `term`, arms 1b–1d.

**1f — `rust_decide_sound`** = `infer_square` ∘ `t1_propositional_soundness_prop` (+ the
`decide_pure = infer then ==` wrapper, mirroring `decide_pure`'s body).

## 3. Scope / fences (honest)

- **Propositional fragment**, exactly matching T1's proven soundness scope. Outside it both sides
  fail-closed (1d), so the transport is total and the soundness composition is clean.
- **Partial-correctness / no-overflow** on the var index cast (`< 2^32`), as with every `rust_*`.
- **Governed on landing**: `#print axioms rust_decide_sound` must be `[propext, Classical.choice,
  Quot.sound]`; add `lean/expected-axioms/dlc-rust_decide_sound.txt` + a `theorem-status` entry;
  `check-axioms` 78→79. Anti-vacuity witness: a concrete accepted `TypingProblem`
  (e.g. `λx:atom0. x : atom0 ⊃ atom0`) on which `decide_pure = ok true` and the `Deriv` is exhibited.
- **Size**: 1a–1f is plausibly 2–4 sub-increments (the reduce-square took several); land each
  green-to-green. 1a+1b (the var arm + helpers) is the highest-risk; the structural arms are
  volume, not risk.
