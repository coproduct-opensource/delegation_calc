# R6.2 increment 1 — `infer_square` + `rust_decide_sound` (design)

*Design memo. 2026-07-24. Branch `dlc-d/phase0-carve`. Phase 1 build increment 1 of the
agent-governance program (`spec/r6.2-agent-service-envelope.md` §3, §6). Design-first because
this is the largest single transport in the program; the proof is staged below.*

---

## 0. Goal

Turn the already-shipped Rust proof-checker (`crates/dlc-core/src/decide.rs :: decide_pure` /
`infer`) into a **verified** one, so a green `cargo build` of an `#[dlc_d::agent_service]` implies a
real typing derivation (hence `capability_safety`), *independent of the macro*. The headline:

```
rust_decide_sound :
  decide.infer ctx term = ok (some prop)  →  Nonempty (Deriv (DecCtx ctx) (DecTm term) (DecPr prop))
```

obtained by composing two pieces:

1. **`infer_square`** (the new transport): the Aeneas image of the Rust checker agrees with the
   hand mirror `decideLean` under decode —
   `decide.infer ctx term = ok ((decideLean (DecCtx ctx) (DecTm term)).map DecPr)` (fences below).
2. **T1 soundness** (already proved, `lean/DLC/Decidability.lean`):
   `decideLean Γ M = some φ → Nonempty (Deriv Γ M φ)`
   (`t1_propositional_soundness_prop`), for the propositional fragment.

So `infer_square` is the whole of the new work; `rust_decide_sound` is a two-line composition.

## 0a. CORRECTION after reverse-engineering (2026-07-24): the decode is CONCRETE work, not "a small missing piece"

`DecTm`/`DecPr` in `Correspondence.lean` are **only type abbreviations** (`syntax.Term → DLC.Term`)
and the decode *functions* are **abstract/deferred** ("Abstract in R2.2b") — the consensus squares
take them as parameters with hypotheses. `infer_square` cannot: `decideLean`'s soundness is about a
*concrete* hand `Deriv`, so stage 1a must **define a concrete decode** over the whole grammar. This
is the bulk of increment 1. It is mechanical (a 1:1 structural map, no mutual recursion — `decProp`
never calls `decTerm`), and every mapping is now fixed (§1a). Reusable idiom (`Correspondence.lean`):
`.val` for `UScalar → Nat` and `Vec/Array → List`; decode structures field-by-field.

### 1a. The concrete decode, fully specified (write this first, green, then the lemmas)

Leaf decodes (hand types: `DLC.{Principal,PrincipalId,Signature,Obligation,ActionId,TimeBound}`,
`DpBudget` in `Graded.lean`, `Label := nucleus_ifc_kernel.CapabilityLattice`):

- `decLabel : ifc.Label → DLC.Label := fun _ => DLC.Label.bottom` — a **total default**. A faithful
  `Vec U32 → CapabilityLattice` decode is *impossible* (established at `lean/DLCD/Transport.lean:85`),
  and it is **sound here** because every label-carrying constructor (`at`, `liftLabel`, `declassify`,
  `command`, `replicated`) is **fail-closed in `decideLean`** — the checker never inspects a label, so
  the decode need only be total, not faithful.
- `decTimeBound t := ⟨t.epoch_ms.val⟩`;  `decSignature s := ⟨UInt8.ofNat s.alg.val, s.bytes.val.map (fun b => UInt8.ofNat b.val)⟩`.
- `decPrincipalId a := ⟨a.val.map (fun b => UInt8.ofNat b.val)⟩` (Aeneas `Array U8 32`);  `decActionId` identical (Aeneas `Vec U8`).
- `decDpBudget d := ⟨d.epsilon_micros.val, d.delta_micros.val⟩` (confirm `Graded.DpBudget` field names).
- `decPrincipal` / `decObligation` — structural 1:1 (`Atom→atom` via `decPrincipalId`; `ActOf→actOf`,
  `Within→within` via `decTimeBound`, `DpBudget→dpBudget`, `Tensor/Lolli/Top/Bot` 1:1).

`decProp : syntax.Prop → DLC.Prop'` — 13-ctor 1:1: `Top→top, Bot→bot, Atom i→atom i.val,
Imp→imp, And→and, Or→or, Says p→says (decPrincipal p), SpeaksFor p q→speaksFor …, At φ ℓ→at (decProp φ) (decLabel ℓ),
Boxed o φ→boxed (decObligation o) …, Within τ φ→within (decTimeBound τ) …, Tensor→tensor, Lolli→lolli,
Replicated φ ℓ→replicated (decProp φ) (decLabel ℓ)`.

`decTerm : syntax.Term → DLC.Term` — 1:1 to the hand ctors `var/lam/app/sign/verify/delegate/attenuate/
boxed/discharge/liftLabel/declassify/now/withinIntro/pair/fst/snd/inl/inr/case/tensorIntro/letTensor/
saysBind/letSays/sfExtract/command/runCmd` (`Var i→var i.val`; sub-decodes via the leaves + `decProp`).
**One read remaining next turn:** dump the *complete* Aeneas `syntax.Term` ctor list
(`lean/DLC/Aeneas/DlcCore/Types.lean`, esp. whether it carries `RunCmd`) to confirm the arm set aligns
exactly with the hand `Term`.

`decCtx c := ⟨c.additive.val.map decProp, c.linear.val.map decProp⟩`.

New file `lean/DLC/DecideDecode.lean` (or a `DecideSquare.lean`), wired into `lean.yml` LIBS; the
decode is a pure-definition, no-`sorry`, immediately-green artifact — the foundation the correspondence
lemmas (§2) build on.

## 1. Why this is tractable (the infrastructure exists for the LEMMAS)

Once the decode (§1a) is defined, the correspondence is the same shape as the landed `decided_square`
/ `byz_decided_square` / reduce-squares, reusing `lean/DLCD/Correspondence.lean`:

- **Decode abbreviations** `DecTm`/`DecPr` (types only, §0a) — the concrete functions are §1a; a
  `DecCtx` is defined there
  (additive/linear are `Vec syntax.Prop`; decode is `List.map DecPr` on each).
- **Clone-is-identity** lemmas `propClone_id`, `termClone_id` (`Correspondence.lean` L200–210) —
  `decide.infer` clones `phi`/`ctx` on every arm; these discharge the clones to `ok`.
- **The reduce-square pattern** (`apply_command`/`reduce_with_fuel` squares) — the established recipe
  for peeling the `Result` monad + `ControlFlow` (`?`-operator via `Try_trait.branch`) that
  `decide.infer` threads on every recursive call.
- **The var-arm Lean correspondence** `ctxLookup_eq_checker_additive` (`lean/DLC/CtxWellFormed.lean`)
  — `ctxLookup Γ i = decideLean Γ (var i)`; the analogue on the Aeneas side (Slice.get ↔ `[i]?`) is
  the var-arm's hard content.

## 2. The proof, staged (each stage a green-to-green increment)

**1a — `DecCtx` + helper lemmas.** Define `DecCtx : judgment.Ctx → DLC.Ctx` and prove:
- `uscalar_cast_index`: the `UScalar.cast .Usize i` on the var index equals `i.val` (no overflow,
  the honest `< 2^32` fence).
- `slice_get_decode`: `core.slice.Slice.get (deref additive) idx` decodes to
  `(DecCtx ctx).additive[idx]?` — the var-arm lookup correspondence (reuse the Vec/Slice lemmas the
  reduce-squares already use).
- reuse `propClone_id` / `termClone_id`; add `ctxClone_id` if needed.

**1b — the var arm.** Compose 1a: `decide.infer ctx (Var i)` decodes to `decideLean (DecCtx ctx)
(var i)`, matching both the additive-hit and the linear-singleton (`len = 1`, `idx = 0`) branches.
This is the hard arm (U32/Slice/index + the linear fallback); everything else is structural.

**1c — the structural arms.** For `Lam`/`App`/`Sign`/`Verify`/`Pair`/`Fst`/`Snd`/`WithinIntro`/
`Inl`/`Inr`/`TensorIntro`/`Case`: each `decide.infer` arm is `branch`-on-recursive-call then rebuild;
each `decideLean` arm is `match`-on-recursive-call then rebuild. With the IH + `propClone_id` +
`Try_trait.branch` unfolding, each is a mechanical `simp`/`split`; the `beq` guards
(`App`, `Case`, `Verify`) reuse `Prop.beq`↔`Prop'.beq` decode-agreement.

**1d — fail-closed arms.** `SaysBind`/`Boxed`/`Declassify`/`LiftLabel`/`Now`/`Delegate`/`Attenuate`
return `none` in *both* `decide.infer` and `decideLean` (both fail-closed outside the fragment) — a
one-line `rfl`/`ok none` each. (This is why the fragment restriction is free: the checker rejects
these, so soundness never needs them.)

**1e — capstone `infer_square`** by structural induction over `term`, arms 1b–1d.

**1f — `rust_decide_sound`** = `infer_square` ∘ `t1_propositional_soundness_prop` (+ the
`decide_pure = infer then ==` wrapper, mirroring `decide_pure`'s body).

## 3. Scope / fences (honest)

- **Propositional fragment**, exactly matching T1's proven soundness scope. Outside it both sides
  fail-closed (1d), so the transport is total and the soundness composition is clean.
- **Partial-correctness / no-overflow** on the var index cast (`< 2^32`), as with every `rust_*`.
- **Governed on landing**: `#print axioms rust_decide_sound` must be `[propext, Classical.choice,
  Quot.sound]`; add `lean/expected-axioms/dlc-rust_decide_sound.txt` + a `theorem-status` entry;
  `check-axioms` 78→79. Anti-vacuity witness: a concrete accepted `TypingProblem`
  (e.g. `λx:atom0. x : atom0 ⊃ atom0`) on which `decide_pure = ok true` and the `Deriv` is exhibited.
- **Size**: 1a–1f is plausibly 2–4 sub-increments (the reduce-square took several); land each
  green-to-green. 1a+1b (the var arm + helpers) is the highest-risk; the structural arms are
  volume, not risk.

## 4b. TWO CAPSTONE SUBTLETIES found while proving (2026-07-24) — the arms are NOT purely mechanical

The var arm is proved (`infer_square_var`, `60125b7`). Assembling the capstone surfaced two real
subtleties the "mechanical shift_corr arms" framing missed:

1. **`beq`-agreement is FALSE in general (label non-injectivity).** `decLabel := bottom` makes
   `decProp` non-injective: `At φ ℓ1` and `At φ ℓ2` (`ℓ1≠ℓ2`) decode to the *same* hand prop, so the
   Aeneas `Prop.eq` (false) and the hand `Prop'.beq` of the decodes (true) DISAGREE. The `App`/`Case`/
   `Verify` arms guard on this equality, so a naive `Prop.eq a b = ok (Prop'.beq (decProp a)(decProp b))`
   helper cannot be proved. **Resolution:** it holds because the checker never *produces* a
   label-carrying type — every label-introducer (`liftLabel`/`declassify`/`command`/`at`-forms) is
   fail-closed in `decideLean` — so the `beq` only ever compares label-free props, where `decProp` IS
   injective. The capstone needs a **range invariant** ("`infer` returns a label-free prop, or none")
   threaded through the induction, or the `beq` arms proved against that invariant. This is the crux.

2. **`cons_a` uses `Vec.insert` = `List.set` with a `0 < length` bound.** The Aeneas
   `alloc.vec.Vec.insert v 0 phi` is `⟨v.val.set 0 phi, …⟩` guarded by `0 < v.length` — i.e. REPLACE,
   and it *fails on an empty `additive`*. But `decideLean.consA φ Γ = φ :: Γ.additive` PREPENDS. So the
   `Lam`/`Case` arms' `decCtx_consA` helper (`decCtx <$> cons_a c p = ok (consA (decProp p)(decCtx c))`)
   is NOT the straightforward prepend it looked like — the Rust `cons_a`'s actual semantics vs
   `consA` must be reconciled (re-read `crates/dlc-core/src/judgment.rs::cons_a`; the checker's own
   T1 soundness already reconciles this, so the fact exists — find where). Verify before assuming.

`ctxClone_id` (the `Lam`/`Case` clone step) is proved (`DLC.CloneId`). Next: resolve (1) via the
range invariant and (2) via the real `cons_a` semantics, then the arms + capstone.

## 4c. ★ BLOCKING FINDING (2026-07-24): Aeneas mismodels `Vec::insert(0)`, so the checker's image is unfaithful at `cons_a`

Pursuing the capstone honestly uncovered a real obstacle, not a proof-engineering one.

**The bug.** Aeneas's standard-library model of Rust `Vec::insert`
(`.lake/packages/aeneas/backends/lean/Aeneas/Std/Vec.lean`) is
`Vec.insert v i x := if i.val < v.length then ok ⟨v.val.set i x, …⟩ else fail arrayOutOfBounds`
— i.e. `List.set` (**replace**) guarded by `i < length`. But Rust `Vec::insert(i, x)` **inserts**
(shifts right) and is valid for `i ≤ length`. Concretely (machine-checked `#eval`):
`alloc.vec.Vec.insert ([] : Vec Nat) 0 7 = fail (arrayOutOfBounds)` — where Rust gives `[7]`.

**Why it blocks `infer_square`.** `decide.rs`'s `cons_a` is `self.additive.insert(0, phi)`
(`judgment.rs:31`), used by every context-extending checker arm (`Lam`/`Case`/says-elim —
`decide.rs:67,235,236,279,289`). So the Aeneas image `decide.infer ctx (Lam φ body)` on an EMPTY
context calls `cons_a` → `Vec.insert [] 0 φ` → **fail**, whereas the hand `decideLean` prepends via
`Ctx.consA` and succeeds. Hence `decOptProp <$> decide.infer = fail ≠ ok (decideLean …)` — the
theorem is **false as stated**, for even `λx:atom0. x`. Worse than a proof gap: the Aeneas image
does not faithfully model the real Rust checker at `cons_a`, so a forced proof wouldn't certify the
deployed `decide_pure` anyway.

**Blast radius (contained).** Only the type-checker uses `cons_a`; the shipped, verified R2
reduce/apply/world_step transport does NOT (confirmed by grep), so no landed theorem is affected —
this is a new obstacle unique to verifying `decide_pure`, which was never transported before.

**Options (a calculus-kernel decision — surfaced to the author):**
- **(A) Change `dlc-core`'s `Ctx` to an Aeneas-faithful representation.** e.g. store `additive`
  reversed and grow it with `Vec::push` (append), which Aeneas models faithfully
  (`push_spec : v1.val = v.val ++ [x]`); de Bruijn indexing flips (var 0 = last). Touches the
  calculus kernel + re-proves `decideLean`/T1/`CtxWellFormed`. Also matches the `decide.rs:7`
  author-note ("upgrade `Ctx::additive` from `Vec<Prop>` to a sorted indexed map"). Large but the
  right long-term fix.
- **(B) Fix Aeneas's `Vec::insert` model upstream** (`insertIdx` with `i ≤ length`, not `set` with
  `i < length`). Makes `cons_a` faithful with zero `dlc-core` change, but is a dependency PR + pin.
- **(C) Rework `cons_a`** to avoid `Vec::insert(0)` (e.g. build `[phi]` and append the old via a
  faithfully-modeled concat), a smaller `dlc-core` change than (A).

Until one is chosen, `infer_square` (and thus `rust_decide_sound`) is parked. The var arm,
decode, `CloneId`, and the range-invariant analysis (decideLean never produces `at`/`replicated`
— label-free, confirmed) all stand and are reused once `cons_a` is faithful.

## 6. CORRECTION (2026-07-24): `cons_a` fixed, and the fragment finding

**§4c's blocker is resolved.** Fix (C) landed (commits `c1fdb92` + `d75299e`): `cons_a`/`cons_l`
prepend via `push` + `extend_from_slice` (Aeneas-faithful; `decideLean`/`Deriv`/T1 unchanged),
and the success-path spec `decCtx_cons_a_ok` is proven axiom-clean with NO overflow hypothesis
(the forward direction fires only where `cons_a` succeeded, which witnesses its own guard). See
memory `aeneas-vec-insert-mismodel`.

**§4c's "range invariant" was WRONG.** `decideLean` DOES produce `Prop'.at` — on `.liftLabel ℓ m`
(`some (Prop'.at φ ℓ)`) and `.declassify ℓ' m π` (`some (Prop'.at φ ℓ')`). So it is NOT label-free,
and the "`decProp` injective on the range" plan does not hold as stated.

**The real finding — `decide.rs` is intentionally MORE PERMISSIVE than `decideLean`.** Arm-by-arm,
the shipped Rust checker `decide.infer` and the verified hand checker `decideLean` **disagree** (Rust
accepts strictly more) on:

| arm | `decide.rs` (shipped) | `decideLean` (verified, T1-sound) | why |
|---|---|---|---|
| `boxed` | `Some(Boxed(o, ty(m)))` — ignores evidence | `none` (fail-closed) | `Deriv.boxI` requires evidence `: atom 0` in **empty** ctx; Rust ignores it, so it accepts underivable terms. Deferred to **T4-ladder R5**. |
| `saysBind` | `Some(Says(prin, ψ))` | `none` | decideLean arm is a stub `none`. |
| `attenuate` | any `ψ` (trusts the claim) | only degenerate `ψ = φ` | non-degenerate narrowing needs a propositional-implication decision procedure (a separate substantial PR); **tested** in `attenuate_narrows_says` — the permissiveness is a design choice, not a bug. |
| `declassify` | ignores `_policy` | requires `π : atom 0` witness | decideLean enforces the policy premise to stay sound vs `Deriv`. |

Consequently a **universal `rust_decide_sound` (green build ⟹ `Deriv`) is FALSE**: on these four
arms `decide.rs` accepts terms the propositional `Deriv`/T1 metatheory cannot derive. Tightening
`decide.rs` to mirror `decideLean` is rejected — it would delete real, tested calculus functionality
(non-degenerate attenuation, obligation boxing) that `decide.rs` deliberately implements ahead of the
deferred modal/IFC soundness metatheory.

**Decision (stronger path, correctly scoped):** prove `infer_square` and `rust_decide_sound` on the
**agreeing fragment** F — the constructors where `decide.infer ≡ decideLean`: `var, lam, app, sign,
verify, delegate, pair, fst, snd, inl, inr, case, tensorIntro, letTensor, letSays, sfExtract,
withinIntro, now, liftLabel, command, runCmd` (per-arm agreement confirmed during the proof;
`delegate`/`declassify` checked carefully). Excluded from F: `{boxed, saysBind, attenuate,
declassify}`, honestly fenced as **deferred T4-ladder metatheory** (the full-calculus `Deriv`
soundness for the modal/IFC/attenuation layer). **The governance-relevant arms are all in F**
(`commit-I` = `command`/`runCmd`; authorization = `sign`/`verify`/`says`/`delegate`/`app`), so the
fragment theorem fully covers the R6.2 agent-service-envelope use-case — the headline "shipped Rust
checker is verified sound for the authorization fragment" stands. Full generality = the T4 ladder.

**Statement (fragment-scoped forward `infer_square`):**
`PropFrag term → decide.infer ctx term = ok (some inferred) → decideLean (decCtx ctx) (decTerm term)
= some (decProp inferred)`, by induction on `term`; then `rust_decide_sound` for `PropFrag` problems
via T1 + a `beq`-agreement lemma (which now must handle `at`-carrying types via the `liftLabel`
label being decoded by `decLabel`, i.e. `beq` on the label component — a per-arm check, not a global
label-free invariant). `PropFrag` = the syntactic predicate carving F (excludes the four arms).
